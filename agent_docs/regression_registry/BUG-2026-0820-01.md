# Bug Entry: `BUG-2026-0820-01`

- **Bug ID**: `BUG-2026-0820-01`
- **Date Resolved**: 2026-08-20
- **Component / Subsystem**: Subagent Worktree Isolation & Orchestrator Gate Protocol
- **Symptom**: Subagents dumped raw source code blocks into markdown chat messages instead of modifying disk files. The Engineering Manager bypassed the subagent pipeline and manually copy-pasted code into workspace files, causing severe context bloat and skipping automated worktree test verification.

---

## 1. Root Cause Summary (5 Whys / Fishbone Result)

- **Primary Root Cause**: 
  1. Lack of an explicit anti-code-dumping constraint in subagent dispatch prompts caused subagents to revert to passive chatbot text generation.
  2. The Engineering Manager collapsed the orchestration boundary by violating the **Absolute Non-Implementation Invariant** (manually copying and pasting code from chat messages into source files instead of rejecting the PR).
  3. Upstream, Antigravity's host `Workspace: "branch"` created worktrees under `brain/`, which tripped artifact path checks when tools were invoked with `ArtifactMetadata`.
- **Why It Occurred**:
  - Subagents lacked direct negative prompt framing against emitting source code in chat text.
  - The Orchestrator lacked an automated PR Rejection Gate to fail subagents that did not modify disk files.

---

## 2. Regression Protection & Invariant Rules

### Invariant 1: Mandatory Direct Disk Tool Execution
- Dispatched subagents MUST apply all code changes directly to disk in `.worktrees/<ticket-id>/` using `write_to_file` and `replace_file_content`.
- Emitting raw code in conversational chat messages is strictly prohibited.

### Invariant 2: Zero Copy-Paste & Automated PR Rejection Gate
- The Engineering Manager is strictly forbidden from copying and pasting code from subagent chat messages.
- If a subagent submits a PR Memo without modifying disk files and running tests, the Engineering Manager MUST immediately reject the PR:
  > *"REJECTED: No disk modifications detected in `.worktrees/<ticket-id>`. Execute `write_to_file` / `replace_file_content` directly on disk and run tests before submitting a PR Memo."*

### Invariant 3: Sprint-Layered Worktrees with Dynamic Concurrency
- Worktrees branch from `sprint/<name>` into `.worktrees/<ticket-id>` on `feat/<ticket-id>`.
- Dynamic concurrency scales freely (3–5+ workers) without arbitrary worker caps.
- Merges go into `sprint/<name>`. Merging `sprint/<name>` into `main` requires full sprint completion and explicit human user approval.
